# Запуск BLAST-поиска по WGS

Инструмент запускается из терминала: передайте FASTA-файл и выбранную группу организмов аргументами команды. Код в Python-скрипте редактировать не нужно.

## Установка

Из корня проекта выполните:

```bash
cd /Users/venikkus/IB/python/blast_api
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
```

При следующих запусках активируйте окружение командой `source .venv/bin/activate`.

## Запуск для Insects

```bash
blast-wgs --query data/queries/KR704917.1.fasta \
  --organism Insects --program blastn \
  --batch-size 250 --output-dir results/insects
```

Если пакет ещё не установлен, используйте тот же интерфейс через Python:

```bash
python search_wgs.py --query data/queries/KR704917.1.fasta \
  --organism Insects --program blastn \
  --batch-size 250 --output-dir results/insects
```

`--organism` принимает имя таксона; параметр можно повторить. Для явного выбора NCBI TaxID используйте `--taxid`, а для исключения ветви таксономии — `--exclude-taxid`. Уточнить параметры можно командой `blast-wgs --help`.

Выберите программу по типу запроса:

| Запрос | Программа |
| --- | --- |
| ДНК против геномной ДНК | `blastn` |
| Белок против переводимых участков генома | `tblastn` |

## Пакетная обработка и продолжение

По умолчанию WGS-проекты разбиваются на группы по 250. Для 10 985 проектов Insects получится примерно 44 задания BLAST, отправляемых последовательно. В одном запуске допускается до 50 пакетов; настройте размер через `--batch-size` и предел через `--max-batches`.

В каталоге результата появятся `manifest.json`, отдельный `batch_NNNN.rid.json` для RID и `batch_NNNN.tsv` для результата каждого завершённого задания. `results.tsv` пересобирается после каждого пакета. Если процесс прервётся, повторите ту же команду с теми же параметрами и каталогом: незавершённый RID будет продолжен, завершённые пакеты пропускаются. Каталог запуска привязан к последовательности и параметрам; для нового поиска выберите другой `--output-dir`.

Каждый пакет — отдельный поиск со своей статистической базой, поэтому E-values из разных пакетов нельзя напрямую ранжировать или сравнивать. Пакетирование позволяет ограничить размер одного задания и возобновить работу; оно не гарантирует более быстрое завершение всего поиска.

## Уже отправленный RID

Если до перехода на CLI был отправлен RID (например, `BWSX16VE014` для поиска сразу по всем 10 985 проектам), это задание остаётся отдельным. Новый пакетный запуск не может превратить его в серию пакетов. Не отправляйте тот же запрос повторно без необходимости; результат старого RID нужно получить отдельно через прежнюю сессию/клиент.

## Интервалы NCBI

Клиент делает паузу перед отправкой поисков, а состояние одного RID проверяет не чаще раза в минуту. Не запускайте несколько массовых поисков параллельно. Для больших очередей и рекомендуемых часов использования ознакомьтесь с [правилами NCBI BLAST API](https://blast.ncbi.nlm.nih.gov/doc/blast-help/developerinfo.html).

## Тесты

```bash
python -m pytest -q
```

## Отбор хитов по порогам из готовых пакетов

Из корня проекта:

```bash
python scripts/select_wgs_hits.py \
  --input-dir results/insects \
  --query data/queries/KR704917.1.fasta \
  --max-evalue 1e-20 \
  --min-identity 90 \
  --min-coverage 80 \
  --sort-by evalue \
  --output results/insects/best_hits.tsv
```

После повторной установки `python -m pip install -e .` также доступна команда
`blast-wgs-select` с теми же аргументами. Скрипт не обращается к NCBI и не изменяет
исходные таблицы. Он читает только `batch_ЧИСЛО.tsv` непосредственно в выбранной
папке. Можно запустить во время поиска: будут обработаны уже сохранённые пакеты;
для новых результатов повторите команду.

Пороговые значения включительны. `--max-evalue` по умолчанию `1e-5`,
`--min-identity` и `--min-coverage` — 0 (без ограничения), `--top-per-batch` — 0.
По умолчанию сохраняются **все accession, прошедшие фильтры**. Ограничить число
accession на пакет можно только явно, например `--top-per-batch 10`.
Внутри каждого пакета остаётся лучшая прошедшая строка для каждого accession;
выравнивания одного accession не объединяются. Повторы между пакетами сохраняются.

`--sort-by` принимает `evalue`, `coverage`, `identity`, `bitscore`. E-value
сортируется по возрастанию, остальные критерии — по убыванию. При равенстве
используются E-value, coverage, identity и bitscore, затем accession. Ранжирование
выполняется отдельно для каждого пакета: E-values разных баз не образуют общий
рейтинг. Лучший E-value не обязательно соответствует наибольшему проценту identity.

Coverage в старых TSV — **оценка**, вычисляемая как
`100 × число символов query_alignment без '-' / длина исходного запроса`.
Это доля запроса (ДНК для blastn, белка для tblastn), а не доля WGS-контига.
Координат запроса в таблицах нет, поэтому точное покрытие объединения нескольких
HSP восстановить невозможно. Если строка содержит перекрывающиеся HSP, оценка
может быть завышена даже при значении менее 100%. Строки с покрытием выше 100%
или несовпадением длины query_alignment с alignment_length исключаются из отбора
и сохраняются в соседний файл `best_hits.review.tsv` (имя зависит от `--output`).
Он содержит исходные поля, имя пакета, номер строки и причину исключения. Скрипт
предупреждает, что выборка неполная, и продолжает обработку остальных строк.
Значения не обрезаются до 100%. Для точного покрытия нужны исходные координаты HSP.

В старом парсере несколько HSP одного accession могли склеиваться, а метрики
оставались от последнего HSP. В новой версии каждый HSP сохраняется отдельно.
Исправление не восстанавливает уже записанные TSV; для восстановления сомнительных
хитов нужен исходный ответ BLAST или повторное получение результата по ещё действующему RID.
Уже запущенный процесс продолжает использовать загруженную ранее версию парсера.

Скрипт принимает один запрос в FASTA или простой последовательностью.
При наличии `manifest.json` проверяет соответствие исходного запроса сохранённому
хешу (включая заголовок FASTA). Альтернатива — `--query-length 1500` вместо
`--query`; тогда правильность длины обеспечиваете вы, хеш не проверяется.

Выход содержит исходные поля, `source_batch`, `rank_in_batch`, `query_length`,
`query_coverage_pct`, `coverage_method=aligned_residues_estimate`.
Файл результата заменяется после успешной обработки всех входных таблиц.
Ошибки чисел или структуры TSV сообщаются с именем файла и номером строки.
