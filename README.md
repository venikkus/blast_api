# BLAST API: поиск по WGS

Python-клиент NCBI BLAST с командой `blast-wgs` для поиска последовательности в WGS-проектах выбранных таксонов. Крупные выборки разбиваются на последовательные задания, сохраняются по пакетам и могут быть продолжены после остановки.

## Установка

Требуется Python 3.8+.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
```

## Быстрый запуск

```bash
blast-wgs --query data/queries/KR704917.1.fasta \
  --organism Insects --program blastn \
  --batch-size 250 --output-dir results/insects
```

Можно передать имя группы/организма несколько раз или указать TaxID напрямую:

```bash
blast-wgs --query query.fasta --taxid 50557 --exclude-taxid 9999
```

Без установки CLI доступен через `python search_wgs.py ...`. Параметры перечислены в `blast-wgs --help`. Инструкция на русском: [docs/RUNNING_RU.md](docs/RUNNING_RU.md).

Результаты и checkpoint-файлы создаются в указанной папке: `batch_0001.tsv`, `batch_0001.rid.json`, `manifest.json` и обновляемый `results.tsv`. Повторите ту же команду с тем же каталогом, чтобы продолжить незавершённый поиск. Не меняйте параметры существующего запуска в этом каталоге.

Размер пакета по умолчанию — 250 проектов; максимум 50 заданий за один запуск. Для 10 985 проектов это 44 последовательных BLAST-задания. Пакетирование ограничивает объём одной отправки и позволяет продолжать поиск, но не обещает ускорения: NCBI требует соблюдать интервалы между обращениями, а каждый пакет — отдельное задание. E-values рассчитываются отдельно для каждой базы-пакета, поэтому напрямую сравнивать их между пакетами нельзя. См. [правила NCBI BLAST API](https://blast.ncbi.nlm.nih.gov/doc/blast-help/developerinfo.html).

Для проверки тестов: `python -m pytest -q`.

## Отбор хитов по порогам

```bash
python scripts/select_wgs_hits.py --input-dir results/insects \
  --query data/queries/KR704917.1.fasta \
  --max-evalue 1e-20 --min-identity 90 --min-coverage 80 \
  --output results/insects/best_hits.tsv
```

По умолчанию сохраняются **все accession, прошедшие пороги**, без ограничения
количества. Для каждого accession внутри пакета остаётся лучшая прошедшая строка. `--sort-by` выбирает `evalue` (по умолчанию),
`coverage`, `identity` или `bitscore`. При необходимости число accession
на пакет можно ограничить явно через `--top-per-batch N`. После установки пакета доступна также команда `blast-wgs-select`.

Coverage оценивается по числу символов выравнивания запроса без пропусков и длине
FASTA. В старых таблицах нет координат запроса: перекрывающиеся HSP могут завысить
оценку. В выходной таблице метод явно указан как `aligned_residues_estimate`.
Строки с покрытием выше 100% или несовпадением длины выравнивания сохраняются
отдельно в `best_hits.review.tsv`; отбор остальных строк продолжается с предупреждением
о неполноте выборки. Новый парсер сохраняет каждый HSP отдельно.
Подробности и значения по умолчанию — в [инструкции](docs/RUNNING_RU.md).

## Структура

- `src/blast_api/` — клиент, CLI и обработчик пакетных заданий.
- `tests/` — тесты без реальных запросов к NCBI.
- `scripts/` — вспомогательные скрипты.
- `data/` — входные данные и FASTA-запросы.
- `docs/` — инструкции.
- `examples/notebooks/` — ноутбуки.
- `archive/legacy/` — прежние скрипты, логи и результаты, сохранённые при уборке.
